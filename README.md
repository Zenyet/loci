# Loci

Chrome 扩展（Manifest V3），替换新标签页，把真实 Chrome 书签变成一张可搜索、可编辑、可聚焦的图谱。

产品规划见 [书签效率与日常小组件迭代计划](docs/plans/2026-09-18-product-roadmap.md)（阶段 A 小组件与阶段 B 快速收藏、收件箱已实现，批量维护等功能仍在规划）。

## 现在的交互模型

- 首页显示书签栏的顶层分组与直属书签，以及“其他书签”、移动设备等来源入口；左下角可筛选来源。受管理目录只读。
- 点击分组节点会进入该分组，子分组和直接书签会在当前层级里散开。
- 点击书签节点会打开书签。
- 搜索支持多关键词，优先匹配标题并展示全部结果；选中结果时，图会切到匹配节点所在层级并平滑跟随聚焦。
- 右键空白可添加书签或新建分组；添加书签默认落在当前层级，首页添加就是 Chrome 书签栏直属书签。
- 右键空白 → 分组管理，可重命名、删除、移动分组并调整分组色调。
- 右上角小组件按钮或设置 → 小组件，可启用天气、时间与今日待办，并调整显示顺序。天气需选择城市；支持三日预报、摄氏/华氏、缓存和离线提示。待办支持本机多标签页同步与删除撤销。
- 设置 → 智能整理，配置模型服务、测试连接，再预览 AI 分组方案、应用或撤销整理。
- 浏览器工具栏 → Loci，保存当前网页，可修改标题和位置；已有相同完整 URL 时提示原位置，由用户选择保留或另存一份。
- 首页左下角 → 收件箱，逐条移动收藏，或勾选后进入 AI 整理。AI 只接收选中书签，预览并确认后才移动。

## Chrome 联动

扩展直接读写 Chrome 本机 API：

- `chrome.bookmarks`：读取书签树；创建、编辑、移动、删除书签和文件夹；监听外部变化并刷新图。
- `chrome.history`：聚合近 30 天访问频次，用于节点权重和最近访问条。
- `chrome.topSites`：当书签为空时，用常用站点做轻量兜底。
- `chrome.storage.local`：保存图连线、图钉位置、设置、待办与天气缓存。

开发模式下没有 Chrome 扩展 API，会自动使用 localStorage mock 数据；安装到 Chrome 后才会接真实书签。

## 常用操作

| 操作 | 入口 |
| ---- | ---- |
| 进入分组 | 点击分组节点 |
| 返回上级 | 顶部当前分组旁的返回按钮 |

| 收藏当前网页 | Chrome 工具栏的 Loci 扩展按钮 |
| 待整理收藏 | 左下角收件箱；移动到其他文件夹即完成归档 |
| 小组件 | 右上角小组件按钮，或设置 → 小组件 |
| 新建分组 | 右键空白 → 新建分组 |

| 编辑/删除书签 | 右键书签节点 |
| 建立关联 | `Shift` + 拖书签节点到另一个书签节点 |
| 删除关联 | 右键连线 |
| 缩放/平移 | 滚轮 / 拖空白 |
| 重置视角 | 双击空白 |
| 设置 | 右上角设置按钮 |
| AI 整理书签 | 设置 → 智能整理 |

## 开发

```bash
npm install           # Node.js 22.12+，使用 package-lock.json 安装依赖
npm run dev          # Vite 预览，使用 mock 数据
npm run typecheck    # TypeScript 检查
npm run check:ui     # 禁止业务界面使用原生下拉框
npm test             # Vitest
npm run build        # 构建 dist/
npm run check        # check:ui + typecheck + test + build
```

## 安装到 Chrome

1. `npm run build`
2. 打开 `chrome://extensions`
3. 启用“开发者模式”
4. 选择“加载已解压的扩展程序”
5. 选择项目里的 `dist/`
6. 打开新标签页
7. 在工具栏的扩展菜单中固定 Loci；在普通网页点击图标，即可收藏当前页

已有安装需在扩展管理页点击“重新加载”，再打开收藏弹窗以使用新增入口。

## 快速收藏与收件箱

默认保存位置是独立的 Chrome 文件夹“Loci 收件箱”，首次成功保存到该位置时创建。Loci 记录实际文件夹 ID，不按名称认领已有文件夹，也不迁移原来的未分组书签。改名或移动文件夹后仍能识别；文件夹被删除或不可写时，下次保存到收件箱会创建新的可用文件夹。

收件箱展示该文件夹的直属书签。用户自行创建的子文件夹仍可在图谱和 Chrome 书签管理器中访问。收件箱条目可单独移动到其他可写位置；多选后进入“智能整理”，仅为选中条目生成方案，新分组创建在书签栏。应用前再次检查条目与目标位置是否仍有效，应用后沿用上次整理撤销。

重复判断仅做标准 URL 序列化，保留路径大小写、完整 query、参数顺序与片段。保存前再次读取书签，串行处理 Loci 内的并发收藏；意外重复点击不会创建多份，明确选择“另存一份”除外。

网页预览不会出现 Chrome 扩展工具栏入口。可点击收件箱中的「体验收藏」（或访问 `/popup.html`），输入测试标题和网址，使用同源 localStorage 演练收藏和跨标签页同步，预览数据不会写入真实 Chrome 书签。安装或重新加载最新 `dist/` 后，工具栏弹窗才会自动读取当前网页。

## 打包

```bash
npm run package:extension
```

脚本会先构建 `dist/`，再生成：

```text
release/loci-0.1.2.zip
```

这个 zip 可用于备份、分发测试或作为 Chrome Web Store 上传前的本地包。

## 权限说明

| 权限 | 用途 |
| ---- | ---- |
| `bookmarks` | 读写 Chrome 书签和分组 |
| `history` | 聚合访问频次和最近访问 |
| `topSites` | 书签为空时显示常用站点 |
| `storage` | 保存设置、连线、图钉、待办和天气缓存 |
| `activeTab` | 点击扩展按钮时读取当前页标题与 URL，用于快速收藏 |
| Open-Meteo 两个域名（可选） | 用户启用天气时申请，用于城市搜索和预报 |

隐私说明见 [docs/PRIVACY.md](docs/PRIVACY.md)。

## 天气服务与验证

天气由 [Open-Meteo](https://open-meteo.com/) 提供。免费端点面向非商业用途；商业化分发前需按实际用途核对[服务方案](https://open-meteo.com/en/pricing)。新用户默认不启用天气，不自动定位，只有选择城市后才查询预报。

当前已验证开发预览中的真实城市搜索、预报、待办跨标签页同步，以及类型检查、自动化测试和构建。Chrome 扩展实装后的可选权限弹窗、拒绝/撤回权限流程仍需人工验收。

快速收藏已验证开发预览中的保存、重复提示、明确另存、收件箱跨页更新、手动归档和所选 AI 范围入口。扩展工具栏的真实 `activeTab` 授权与弹窗生命周期仍需在 Chrome 实装验收；自动化测试中的 AI 使用 mock，不会发送真实收藏或消耗用户额度。
