# 新小组件：市场速览与日常工具

日期：2026-09-22。状态：首批组件已实现于工作区，未发布。设计交互预览使用明确标识的合成数据；正式组件没有演示报价，真实行情需要用户配置自己的 Tushare Token。

## 本轮实现记录

- 组件库增加市场速览、便签、专注计时、收藏回访，默认关闭；可排序、固定到首页，桌面最多显示 3 个固定工具，900px 以下显示 1 个，其余进入「更多」。旧设置按原顺序迁移。
- 市场接入 Tushare HTTPS 的 `rt_idx_k`、`rt_k` 和交易日历 `trade_cal`。上证、深证、创业板作为默认指数；沪深 A 股首版按交易所和 6 位代码添加，最多 10 个自选，可排序、删除撤销、设为首页关注项。首版没有名称搜索、分时、ETF 或北交所。
- Token 通过现有本地设置存储，仅在用户点击连接时申请行情域名权限。缓存键使用凭据摘要隔离账号，原始 Token 不进入缓存或错误文案。指数和个股分别缓存、处理错误，支持部分缺失、保留旧报价、限流退避、手动刷新节流和多标签页 Web Locks 协调。页面隐藏会取消请求。
- 自动读取交易日历；不可用时显示「交易状态待确认」并降低刷新频率，不使用行政调休日历判断交易日。行情时间和请求时间分开保存；没有供应商完整时间戳时明确提示，整体时效不承诺实时。
- 便签支持 5000 字自动保存、本地同步、复制、选中文字或首行转待办，保存失败保留当前输入并允许重试。
- 专注支持 1–180 分钟与 5 分钟休息、暂停/继续、关联待办、结束后手动完成待办。按本地持久化的结束时间恢复，刷新或休眠不会按计时器调用次数漂移，不发送系统通知。
- 收藏回访支持全部收藏或指定文件夹及其子文件夹、每日候选、换一条、今天不再显示；只打开有效 HTTP(S) 链接，不修改原书签。
- 下拉使用项目 `Select`、`GroupSelect`，关闭使用 `CloseButton`；在 `TextInput` 中扩展共享外观的 `TextArea`。同时补齐 `GroupSelect` 的唯一菜单 ID、可访问名称、Home/End/Tab 键盘行为和弹窗边界计算。

已做浏览器验证：组件启用、便签转待办、关联待办选择、计时整页刷新恢复、收藏文件夹键盘选择、Escape 分层关闭、360px 窄屏面板与下拉边界。真实行情尚未通过账号验证：目前没有实际 Token，接口行为与异常路径使用模拟响应测试；HTTPS 服务地址仅完成连通检查。

以下为完整设计方案；其中未在本节列出的分时图、名称搜索、重要日期、世界时钟、阅读队列等仍为后续规划。

## 设计结论

增加一张「市场速览」，把 A 股大盘和自选股放在同一组件里。沿用现有“顶部摘要 → 点击展开”的交互，默认关注上证指数、深证成指、创业板指；用户可以切换摘要关注项。第一批扩展优先做便签、专注计时、收藏回访，再做重要日期与世界时钟。

设计方向是安静、紧凑的桌面工具：复用 Loci 的主题色、圆角和浮层，数字使用等宽数字。红绿只用于涨跌，不作为大面积卡片底色；不自动滚动行情，不用闪烁吸引注意。

## 1. 首页与组件库

- 保留时间天气卡与今日待办；新增组件默认关闭。旧用户的启用状态、排序、城市与日历设置不变。
- 市场摘要显示“上证指数 / 最新点位 / ±涨跌幅”；空间够时再显示第二个指数。摘要不轮播，点击打开详情。
- 首页建议时间天气 + 最多 3 个用户置顶的工具摘要；更多组件收进「更多」。窄屏缩为时间天气 + 1 个置顶摘要 + 更多，不能挤压搜索与图谱操作区。
- 点击原来的“添加小组件”进入组件库：分类为「日常」「效率」「市场」「收藏」。每项提供可辨认的缩略预览、功能描述、是否联网、添加/已添加。
- 「添加」表示进入组件库中的已启用列表，达到首页容量后进入更多；「置顶」另行控制首页展示。关闭保留配置，删除数据单独操作。
- 同一时间展开一个组件，详情跟随入口定位并做视口碰撞处理。桌面行情面板建议 400–440px 宽，窄屏为视口宽度减两侧边距；不要给所有组件写死同一纵向位置。

## 2. 市场速览

### 摘要与展开

| 层级 | 展示内容 | 交互 |
| --- | --- | --- |
| 首页摘要 | 选定指数或个股、最新点位/价格、涨跌幅；过期或离线标记 | 点击展开上次所在页 |
| 大盘页 | 3 个指数的名称、点位、涨跌额、涨跌幅 | 点击指数查看详情，可设为首页摘要 |
| 指数详情 | 最新值、昨收、今开、最高、最低；有相应数据权限时显示当日分时 | 切换关注指数、手动刷新 |
| 自选页 | 最多 10 个标的；名称、市场代码、价格、涨跌幅 | 搜索添加、移除并撤销、上下调整顺序 |
| 固定页脚 | 数据源、行情时间、数据时效说明 | 刷新；有合法详情链接时可打开原站 |

首版先覆盖沪深 A 股和上证、深证、创业板核心指数。指数与股票按 `market + instrumentType + code` 区分，不能只用裸代码：上证指数和深圳股票可能同为 `000001`。北交所、ETF、港美股逐项确认数据覆盖后再开放，不能仅增加一个市场选项就承诺支持。

自选只记录关注列表。首版不记录持仓、成本、收益，不提供交易入口和买卖建议。按名称或代码搜索，结果必须同时显示交易所与标的类型；首次打开自选页是空状态，不替用户选股。

### 可用状态

| 状态 | 产品行为 |
| --- | --- |
| 未连接 | 展示数据源说明和主动连接入口，不自动请求权限；不出现演示报价 |
| 首次加载 | 数字位置用占位，保留名称；不显示 0.00 或虚构涨跌 |
| 已有缓存、刷新中 | 保留原数据及其时间，显示轻量更新状态 |
| 有延迟 | 写明供应商声明的延迟；时效未知则显示“时效未确认”，不用“实时” |
| 午间休市 / 竞价 / 已收盘 | 独立显示交易状态与行情日期；有数据源状态时优先采用 |
| 节假日 / 周末 | 展示最近交易日及其收盘值，不把自然日变化当作新交易日 |
| 网络失败 / 限流 | 保留最近成功值，标记“上次记录 / 更新失败”，遵守重试等待 |
| 部分标的失败 | 仅失败项显示状态，成功项继续可读；不将空值处理为零涨跌 |
| 停牌 / 无报价 | 明确标识；不绘制虚假的水平分时线 |
| 无分时数据 | 隐藏图表，显示“该数据源暂不提供分时”；不把数次轮询拼成完整当日走势 |

默认采用红涨绿跌，可设置绿涨红跌或单色；始终保留正负号和涨跌文字。涨跌幅以数据源的昨收计算，昨收为零或缺失时显示“—”。不同指数成交额可能包含重叠证券，不能相加冒充全市场成交额；涨跌家数也必须有独立、明确的统计范围。

### 刷新与交易日

设计目标：摘要在页面可见且相关市场开市时约 60 秒刷新，展开页约 30 秒；实际频率受供应商额度限制。页面隐藏、组件关闭后停止轮询；休市时读缓存并按需刷新，开盘、午后恢复、收盘后各做边界校验。手动刷新也受节流限制。

统一使用 `Asia/Shanghai` 处理 A 股时间。交易所交易日历与现有生活日历分开：调休工作日不能据此判断股市开市。竞价与连续交易是不同状态；股票的开盘集合竞价、连续竞价和收盘集合竞价时间可参考[上交所股票投资说明](https://one.sse.com.cn/onething/gptz/)。若交易日历缺失，显示“交易状态待确认”，不靠周一至周五作确定判断。盘后固定价格交易如不接入，要明确本组件展示竞价交易时段行情。

## 3. 行情数据的可行路径

目前项目是 Chrome Manifest V3 新标签页扩展，manifest 尚未声明行情域名，也没有行情后端。正式功能需要单独完成供应商选型与连接验证。

| 路径 | 适合范围 | 要补齐的条件 |
| --- | --- | --- |
| 合成数据预览 | 本轮设计评审 | 每处行情都能看到演示标识；不得作为上线数据回退 |
| 用户自己的 API 凭据 | 个人验证、小范围试用 | 确认 HTTPS、浏览器扩展访问、额度、许可范围；凭据仅保存在本机，不写日志或同步导出 |
| 统一行情代理服务 | 面向普通用户的正式版 | 供应商允许产品展示的授权、后端凭据保护、缓存、配额与维护预算；扩展不能内置共享密钥 |

已核实 Tushare 官方有[指数实时日线 `rt_idx_k`](https://tushare.pro/document/2?doc_id=403)和[沪深京实时日线 `rt_k`](https://tushare.pro/document/2?doc_id=372)，二者均标明需要单独开通权限。实时日线快照能支撑最新值、涨跌与当日高低，不能单凭这个接口得到完整分时轨迹。[当日累计分钟 `rt_min_daily`](https://tushare.pro/document/2?doc_id=457)另有实时分钟权限要求，且此页描述的是股票，不能据此假定指数也受支持。费用和限额以[供应商权限表](https://tushare.pro/document/1?doc_id=108)及具体协议为准，本方案不承诺免费实时数据。

这些文档验证了数据能力的存在，尚未验证 Loci 的接口连通性或分发许可。交易所也提供[获实时行情许可的供应商名单](https://english.sse.com.cn/markets/dataservice/list/)，可用于后续选型。不能把网页上能读取到的行情接口直接当成长期可分发的公共 API。

建议先用一个已获授权的数据源完成“3 指数快照 + 自选报价”，再开分时图、市场宽度、ETF。实际授权与连通性确认前，市场组件保持设计状态；本地工具组件可以独立落地。

## 4. 继续扩展：与 Loci 已有能力连接

| 优先级 | 组件 | 收起时 | 展开后与首版边界 | 与已有功能连接 |
| --- | --- | --- | --- | --- |
| P1 | 便签 | 第一行内容或“随手记” | 一张纯文本、自动保存、复制、明确保存状态；关闭保留 | 选定一行转为待办，成功后保留原文并提示 |
| P1 | 专注计时 | 剩余时间 + 当前任务 | 25/5 分钟、自定义时长、暂停/继续/结束；刷新后按结束时间恢复 | 关联一条已有待办；完成计时后由用户决定是否完成待办 |
| P1 | 收藏回访 | 一条值得重看的收藏 | 选文件夹；打开、换一条、近期不再提示；每天固定候选 | 使用现有书签与文件夹；本地规则，不增加 AI 调用 |
| P2 | 重要日期 | “距旅行还有 18 天” | 最多 3 个公历日期；置顶一个；区分倒数、今天、已过 | 从现有日历选日期；首版不做农历生日重复 |
| P2 | 世界时钟 | 一个协作城市的时间 | 最多 3 个 IANA 时区、跨日标识、工作时段对照 | 收进时间天气卡的扩展页，减少首页独立卡片 |
| P2 | 阅读队列 | “待阅读 4 篇” | 用户手动标记下一篇、已读、稍后；不自动推断读完 | 与收件箱及书签关联，URL 去重；书签是内容来源 |
| P3 | 汇率换算 | 用户指定的一组货币对 | 金额换算、汇率日期与来源；明确参考汇率 | 复用行情数据状态和缓存机制，供应商单独确认 |
| P3 | RSS 摘要 | 用户订阅的一条标题 | 最多 3 个订阅源、发布时间、已读、打开原文 | 用户手动选择文章加入阅读队列；需要处理跨域和内容清洗 |

推荐的组合：

- 关注市场：时间天气 + 市场速览 + 待办。
- 工作专注：时间天气 + 待办 + 专注计时；便签进入更多。
- 知识整理：时间天气 + 收藏回访 + 阅读队列；市场按需开启。

组合只作为组件库里的推荐，不自动启用任何组件。新闻热榜、复杂持仓报表、AI 选股暂不纳入：当前最有价值的是快速看到自己关心的信息、完成一个小动作。

## 5. 工程落点

### 小步扩展现有组件结构

1. 在 `src/types.ts` 中按批次增加 `market`、`notes`、`focus` 等设置，`normalizeWidgets` 补默认值；保持 `weather → clock` 的合并卡片兼容逻辑。
2. 把 `WidgetDashboard.tsx` 当前大条件分支拆成独立摘要和详情组件。用轻量注册表统一标题、分类、摘要、面板、设置；不在这一轮建立插件运行时。
3. `widgetCardOrder` 与首页置顶列表分开，前者控制启用组件顺序，后者解决首页容量。旧 order 迁移时保留已启用项的相对顺序，不能让新组件抢占。
4. 设置复用 `SettingGroup`、`SettingRow`、`Switch`；下拉必须用 `Select`，文件夹用 `GroupSelect`，输入用 `TextInput`，关闭复用 `CloseButton`。
5. 新服务建议为 `services/market.ts`、`hooks/useMarket.ts`、`components/widgets/MarketWidget.tsx`。网络权限只在用户主动连接时申请，按供应商域名加入可选权限。

### 数据契约与缓存

行情服务统一输出标的 ID、名称、交易所、类型、币种、价格精度、现价、昨收、行情时间、取回时间、交易日、交易状态、数据源、供应商声明的延迟。行情时间与请求时间分开保存；不能刚取回昨日收盘价就标成“刚刚实时更新”。

快照、分时、搜索、交易日历作为独立能力声明。分时点必须带数据源时间戳和交易日，午休分段；跨日清理旧序列。数据切源、换标的、关闭组件时取消或丢弃旧请求；缓存键包含来源、交易所、标的类型、代码和交易日。

多个新标签页共享短期缓存并协调请求，避免每开一页都启动独立轮询。可先用 Web Locks 与 BroadcastChannel 做一个可见页面的请求协调，并提供能力缺失时的节流兜底；不要假设现有项目已经有常驻后台服务。

便签与计时状态沿用本地存储同步模式；计时以结束时间计算。新标签页全部关闭时，首版不承诺系统提醒，重开后恢复状态。若后续提供关闭页面后的提醒，再单独引入扩展后台与通知能力。

## 6. 分期与验收

**第一步：设计确认与数据打样。** 确认市场摘要密度、大盘/自选结构、组件库和三个优先扩展；验证单一数据源的三个指数、两个测试股票、限流、时效、许可和扩展访问。没有供应商权限时只使用演示原型，不宣称可用行情。

**第二步：首批功能。** 先落组件注册与摘要溢出，再独立交付便签；行情数据打样通过后上线市场快照与自选。正式市场首版可以暂不带分时图。

**第三步：联动。** 增加专注计时和收藏回访；依据实际使用情况决定是否增加倒数、阅读队列和世界时钟。

验收要点：

- 市场：代码歧义、前收缺失、停牌、休市、午休、跨日、延迟、部分失败、撤权、限流均可辨认；不显示假报价，不用行政调休日历推导股市开市。
- 页面：组件开启后搜索与图谱仍可操作；只有展开面板时拦截图谱交互；窄屏摘要进入更多且面板不越界。
- 可访问性：键盘能添加/移除/排序；Escape 先关下拉再关面板；关闭后焦点回到入口；正负号与状态文字不依赖颜色。
- 性能：隐藏页停止轮询，多页不会重复请求，组件未启用不发网络请求。
- 回归：旧天气、日历、待办、顺序与本地数据保持；正式 UI 修改后运行 `npm run check:ui` 及相应行为测试。

设计阶段交付了这份文档和可交互的市场预览；预览中的切换、关注项和收藏操作仅用于评审，不写入实际扩展配置。

设计预览验证：浏览器中检查了指数切换、首页摘要切换、自选搜索与增删、便签转演示待办、计时开始/暂停/模式切换、收藏回访与 Escape 收起；检查了 320px、360px 和常规宽度，修正窄屏指数数字溢出。正式组件的实现与验证范围见文档顶部「本轮实现记录」。
