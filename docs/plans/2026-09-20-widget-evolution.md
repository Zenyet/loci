# 日常小组件：合并卡片与下一步方案

日期：2026-09-20。时间天气合并、定位流程和日历首版已实现；其他候选仍为方案。

## 本轮实现

- 首页将时间、日期、天气放在同一张紧凑卡片里。天气区域点击展开详情，日期始终显示；时间和天气可分别开关。
- 设置页合并配置区和排序项，兼容旧的时间、天气、城市、温度单位及顺序，不清空原设置。
- 城市选择增加「使用当前位置」：主动点击 → 申请城市识别服务权限 → 获取一次设备位置 → 识别城市 → 保存城市及约略坐标 → 沿用天气缓存与刷新逻辑。
- 定位拒绝、超时、无定位能力、城市识别失败均可退回手动搜索；不开启 IP 定位兜底，不持续跟踪。关闭面板或改用搜索会忽略未完成结果。
- Chrome 的 `geolocation` 不能列为可选扩展权限，必须声明于 manifest；城市识别域名权限单独按点击请求。读取设备位置仍由按钮触发。[Chrome 文档](https://developer.chrome.com/docs/extensions/reference/api/permissions)
- BigDataCloud 客户端接口用于即时设备坐标识别城市；其服务会接收坐标与 IP，并利用匿名配对改进定位数据。Loci 仅保留两位小数的约略坐标。测试使用 mock，不把合成坐标发送到要求真实设备位置的服务。[服务与使用要求](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api)

## 已实现：日历首版

日历接在合并卡片的时间区域：点击时间、日期或区域内留白均可展开月历，日期居中并使用主题色。首版按中国大陆使用习惯设计，显式标注节假日地区，与天气城市分开。

| 范围 | 首版行为 |
| --- | --- |
| 月历 | 周一为一周起点，切换月份、返回今天、查看选定日期，跨年可用 |
| 农历 | 每格显示农历日，初一显示月份；选中后显示完整农历日期、闰月信息 |
| 节假日 | 区分传统节日名称与法定放假安排；用「休／班」标记实际放假和补班 |
| 摘要 | 展示当天状态与下一次已确认的假期，不用假数据填补未知年份 |
| 离线 | 月历、农历和已收录年度安排均离线可用 |
| 开关 | 可分别关闭农历与节假日显示；不申请账号或个人日历权限 |

数据方案：

1. 农历优先使用浏览器原生 `Intl.DateTimeFormat` 的 Chinese calendar，在本地按用户日历日期转换；不请求远程「农历 API」。用春节、闰月、除夕、跨时区和月界测试验证，不按数字月份自行推算。[Intl 文档](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat)
2. 法定节假日和补班按国务院每年通知整理为版本化数据，记录地区、年份、来源及更新时间，随扩展版本更新。后续有稳定维护流程再做远程数据更新。
3. 未收录年度显示「该年度放假安排待更新」，仍显示农历；不能把周末直接当作最终休息日，也不能套用上一年调休。
4. 已收录 2026 年官方通知，包含 33 天放假与 6 个补班日；9 月 20 日为补班日，9 月 25 日开始中秋假期，10 月 10 日为补班日。[2026 年安排（政府网站转载原通知）](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)

实现说明：

- 年度数据位于 `src/data/holidays.ts`，每年保留版本、发布日期、来源与完整放假区间。增加新年度时核对全部补班日，并更新数据验收测试。
- 月历支持 1901–2100 年；当前仅 2026 年有放假安排，其余年份仍可查看公历与农历。传统节日与「休／班」分别计算，不把节日名称当作放假依据；首版不包含二十四节气。
- 使用设备本地日期作为今天，以不带时区转换的公历日期计算农历与天数；不跟随天气城市改变日期。
- 键盘支持方向键、Home/End、Page Up/Down，Shift + Page Up/Down 跳年。Escape 和统一关闭按钮均恢复入口焦点。
- 设置增加「显示农历与节日」「显示放假与调休」，旧设置自动补齐这两个显示偏好，保留原来的天气、时间与排序。

首版暂不接 Google、Apple、Outlook 日历；个人日程同步是另一项功能，涉及授权、重复事件、时区及增量同步，应单独评估。

## 其他可挖掘的小组件

| 优先级 | 候选 | 为什么值得做 | 最小可用范围 |
| --- | --- | --- | --- |
| P1 | 便签 | 新标签页随手记，和现有待办互补 | 一张纯文本便签、自动保存、复制；可手动把一行转为待办 |
| P1 | 专注计时 | 把待办和收藏阅读接起来 | 25/5 分钟与自定义时长、关联一条待办、暂停/继续；用结束时间计算，刷新或休眠后不漂移 |
| P2 | 重要日期倒数 | 提醒下一次考试、出行、纪念日 | 最多 3 个日期、置顶一个；先做公历日期，农历生日重复单独设计 |
| P2 | 收藏回访 | 发挥 Loci 已有书签的优势 | 用户选一个文件夹，每日显示一条待回访收藏，可跳过；首版使用本地规则，不调用 AI |
| P2 | 世界时钟 | 跨时区协作有明确用途 | 最多 3 个时区，与本地时间对比，显示跨日差异 |
| P3 | 天气出行信息 | 增强现有天气而不增加独立卡片 | 日出日落、体感与降水提示；空气质量另接数据源并标注更新时间与来源 |

建议顺序：日历 → 便签 → 专注计时 → 倒数或收藏回访。首屏以一张时间天气卡片和少量工具入口为主，按需展开，避免堆满资讯。

验收重点：打开新标签页是否更快得到有用信息、是否减少切换页面；不以停留时长或组件数量为目标。
