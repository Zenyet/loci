# Loci 产品迭代计划：书签效率与日常小组件

- 日期：2026-09-18
- 状态：2026-09-19 已实现阶段 A 与阶段 B 的代码和自动化验证；扩展实装权限验证、完整尺寸覆盖与性能基线仍待验收。阶段 C、D 未实现。
- 依据：当前仓库代码、README、开发模式界面走查，以及天气服务与 Chrome 官方文档。
- 用户方向：继续完善书签使用流程，同时增加天气等日常小组件。
- 优先级假设：主要服务拥有较多书签、每天频繁打开新标签页的个人用户；尚无用户行为数据，后续通过试用验证。

## 1. 产品目标

把 Loci 做成每天打开都实用的个人起始页：中心区域用于找回和组织收藏，边缘区域提供天气、时间、待办等轻量信息。

两条产品主线：

1. 书签效率：快速收藏 → 收件箱 → 整理 → 搜索与再次打开。
2. 日常使用：打开新标签页 → 看时间与天气 → 查看今天要做的事。

小组件的价值以信息是否有用、操作是否方便衡量；书签能力以能否成功找到和打开目标页面衡量。停留时长不作为主要成功指标。

## 4. 小组件产品方案

### 4.1 布局与统一交互

- 顶部信息区放日期、可选时间、天气摘要，沿用现有页面的视觉风格。
- 待办使用顶部紧凑工具入口，显示摘要与数量，点击在左侧展开；后续便签沿用这一交互。
- 设置新增“小组件”分类，提供启用、停用、区域内排序和各组件设置。
- 首页提供可发现的“添加小组件”入口；首次使用提示可关闭，不反复出现。
- 首版使用固定信息区和工具区，排序通过上移/下移完成；自由拖拽、尺寸调整留作后续需求。
- 默认保留日期。天气、待办由用户启用；升级不改变用户现有首页布局。
- 同时只展开一个工具浮层。进入搜索、设置或书签编辑时收起组件浮层；天气缓存更新可以继续。
- 输入待办或城市时，文字输入和快捷键只作用于当前组件，不触发图谱搜索、拖动或连线。
- 窄窗口将工具入口合并到可展开区域，避免遮挡搜索、设置和分组返回按钮。
- 支持浅色、深色、壁纸背景和减少动效；图标具备文字标签，交互支持键盘与焦点恢复。

### 4.2 首批与候选组件

| 组件 | 用户场景 | MVP | 排期 |
| --- | --- | --- | --- |
| 天气 | 打开页面了解出行条件 | 城市、当前温度、天气状态；展开查看体感、当日高低温、降水概率和三日预报 | 首批 |
| 时间 / 日期 | 快速看时间与日期 | 时间开关、12/24 小时制、系统时区；分钟级更新 | 首批 |
| 今日待办 | 记下并完成今天的几件事 | 紧凑摘要、任务列表、完成状态、删除撤销、本地保存 | 天气之后 |
| 专注计时 | 从准备进入专注状态 | 25/5 分钟预设、自定义时长、开始/暂停/结束，页面内完成提示 | 第二批候选 |
| 便签 | 临时记录想法与文字 | 单张纯文本便签、自动保存、复制 | 第二批候选 |
| 月历 | 查看日期、星期和月份 | 本地月历、切换月份、返回今天 | 第二批候选 |
| 世界时钟 | 跨时区沟通 | 自选 2–3 个城市，显示对应时间和日期差异 | 后续候选 |
| 每日一句 | 少量个性化内容 | 本地内容按日切换，可隐藏 | 后续候选 |

外部日历同步、资讯流、邮件和第三方小组件市场属于独立范围，等首批使用反馈后再评估。

### 4.3 天气 MVP 详细流程

1. 用户在“小组件”中启用天气，看到城市选择入口和天气服务说明。
2. 用户输入城市名，结果显示城市、省/州、国家以区分同名地点，确认一个结果。
3. 首页显示“城市 · 天气图标 · 温度”。天气数据独立异步加载，书签画布和搜索立即可用。
4. 点击摘要展开天气详情，显示体感温度、当日高低温、当日最大降水概率、未来三日预报、更新时间与数据来源。
5. 用户可以切换城市、切换摄氏/华氏、手动刷新、关闭组件。

首版使用手动城市选择，默认不推断用户所在地。自动定位作为后续可选能力单独评估。

**状态与刷新规则**

- 未配置：显示“选择城市”，不展示虚构天气或默认城市。
- 首次加载：仅组件区域显示加载状态。
- 缓存有效：立即显示缓存；建议新鲜期 60 分钟，作为可调整的产品参数。
- 缓存过期：先展示带更新时间的旧数据，再异步更新；超过 6 小时改为明确的历史状态，不把旧温度标成当前天气。
- 请求失败或离线：有缓存则提示数据较旧；无缓存则显示“暂时无法获取天气”和重试入口。
- 关闭组件：取消当前请求与刷新任务；保留城市偏好以便重新启用。
- 隐藏标签页停止周期刷新；重新可见时先检查缓存。快速切换城市时取消或忽略旧请求结果。
- 页面内请求合并，多标签页共享缓存；开发时验证同城同时打开多个新标签页时的请求去重。
- 请求设置超时、重试冷却；遇到限流遵循服务端指示，避免循环重试。

**数据源建议与发布条件**

- 候选使用 Open-Meteo：预报 API 可提供温度、天气状态、体感、逐日高低温和降水概率；城市选择使用其 Geocoding API。[预报文档](https://open-meteo.com/en/docs) · [城市搜索文档](https://open-meteo.com/en/docs/geocoding-api)
- 官方当前将免费 API 定位为非商业用途，且不保证服务可用性。首版接入验证可以先评估这一方案；公开分发或商业化时需按实际用途复核服务方案，不能假设可长期免费商用。[服务方案](https://open-meteo.com/en/pricing)
- 开发第一步验证中文城市搜索、目标用户网络环境可达性、响应时间、数据来源署名要求和扩展内请求行为，再确定最终 provider。
- 城市搜索发送用户输入的城市文字；天气请求发送所选城市坐标和查询参数。服务端也会接收到常规网络连接信息。书签、历史记录、待办和 AI Key 不进入天气请求。
- 扩展侧按功能声明必要的天气服务域名，优先使用启用天气时申请的可选 host 权限；拒绝或撤回权限有对应状态。开发环境普通网页的 CORS 与已安装扩展的行为分别验证。[Chrome 网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests) · [Chrome 可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)
- provider 通过独立接口接入。若未来服务需要产品级密钥，另行确定服务端方案，不把共享私密密钥写入扩展包。

### 4.4 待办 MVP 详细范围

- 收起时显示未完成数量和首条任务；展开后可以新增、完成、取消完成。
- 新用户初始列表为空，使用提示性空状态；开发示例任务不进入真实用户初始数据。
- 保留已有用户数据，加载完成前避免新操作被异步旧数据覆盖。
- 删除后支持短时撤销；完成项可折叠。
- 使用原生按钮、复选框等可访问控件，补齐现有组件的键盘操作。
- 两个新标签页对同一任务的操作应可见；实现存储变化订阅，并明确并发合并规则。
- 后续专注计时基于持久化结束时间计算，验证刷新、休眠和多标签页场景；首版计时完成仅提供页面内反馈，关闭全部页面后的系统通知另行规划。

## 5. 书签主线的 MVP 与验收

### A：数据覆盖、搜索与入口

- 读取所有支持的书签根目录，按实际节点类型识别来源，兼容旧环境；受管理目录正确反映只读能力。
- 来源筛选属于 Loci 视图设置，不移动 Chrome 原书签。
- 将当前围绕 `barId` 的根级导航、默认新增位置和 AI 整理目标一并检查，明确虚拟来源节点与真实文件夹的区别；不能仅扩展读取后沿用所有书签都属于书签栏的假设。
- 搜索支持全部结果、多关键词、标题精确匹配和前缀匹配优先，随后结合访问频次排序。
- 首页补充可见的添加、管理和操作帮助入口，首次使用可发现核心能力。
- 验收：不同根目录的书签可找到并打开；第 9 条及以后的结果可访问；搜索后进入正确层级；只读节点不可误操作。

### B：快速收藏与收件箱

- 工具栏扩展按钮保存当前页标题与 URL，可修改标题与目标位置。
- 收件箱采用明确的 Chrome 文件夹承载，保存其实际 ID；已有“未分组”书签不自动全部迁入收件箱。
- 已收藏相同 URL 时显示现有位置并允许用户选择行为；首版使用保守规则，不随意去除会影响内容的 query 参数。
- 收件箱支持逐条移动和选择多条生成 AI 方案；未配置 AI 时可以完成手动整理。
- 验收：从任意正常网页完成收藏后，新标签页可立即找到；保存失败有反馈，重复点击不意外创建多条。

### C：批量维护、恢复与备份

- 列表与图谱共享数据、搜索范围和当前分组，列表支持多选与批量移动、删除。
- 批量操作在执行前展示影响数量，部分失败逐项反馈，并提供可执行的恢复记录。
- 通用撤销记录新增、编辑、移动、删除的必要快照；恢复被删除书签可能产生新 ID，连线、布局等关联数据需建立映射。
- 清理首版识别完全重复 URL 和空文件夹，人工选择保留项；失效链接检测另开范围，处理登录、限流等误判。
- 备份使用带版本的数据格式，导出范围明确列出书签副本与 Loci 元数据，默认排除 API Key 和浏览历史。
- 恢复先预览差异，依据 URL、路径和用户选择重建对应关系；不能假设书签 ID 跨设备稳定。
- 验收：批量操作中途失败可辨认已完成项；恢复不会静默覆盖；导出与恢复后连线、颜色等数据映射正确。

### D：标签、备注与工作区

- 标签和备注作为 Loci 元数据保存，支持搜索；一个书签可以属于多个虚拟集合。
- 智能集合以可理解的筛选规则生成，例如“带设计标签的待阅读内容”。
- 工作区引用不同文件夹的书签，支持一键打开，展示将打开的页面数量。
- 图谱关联可附说明，书签详情中可查看相关内容及关联原因。
- 验收重点是用户是否更容易找回内容、启动一组工作页面，再决定是否扩展更复杂的语义检索。

## 6. 首批开发任务与代码落点

任务可以按独立交付单元拆分，不要求一次合并整个路线。

| 顺序 | 任务 | 主要代码落点 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 书签来源与搜索补齐 | `chromeApi.ts`、`types.ts`、`Graph.tsx`、mock 数据 | 所有支持来源可读；全部结果可选；根级导航正确 |
| 2 | 小组件配置与容器 | 新建 `components/widgets/`；修改 `types.ts`、`useSettings.ts`、`Tweaks.tsx`、`App.tsx` | 开关、排序、配置迁移、浮层互斥可用 |
| 3 | 天气 provider 验证 | 新建 `services/weather/` | 确认可达性、字段、城市结果、服务方案和权限行为 |
| 4 | 天气缓存与状态 | 新建 `useWeather`、weather cache/provider 模块 | 超时、过期、离线、城市切换、多标签页请求行为符合定义 |
| 5 | 天气与时间界面 | 新建 `WeatherWidget`、`ClockWidget`；复用 `useClock` | 摘要与详情完整，键盘、主题、窄窗口均可用 |
| 6 | 今日待办接入 | 包装或调整 `TodoPanel`、`useTodos`，复用存储层 | 空数据初始化、真实旧数据保留、删除撤销和跨页同步 |
| 7 | 发布前验收与文档 | manifest、README、PRIVACY 与相关测试 | 扩展实装验证、隐私说明一致、检查命令通过 |

配置与架构约定：

- 小组件设置使用版本化结构，按组件 ID 保存启用状态、位置和配置；缺字段时使用兼容默认值。
- 天气缓存和待办数据独立保存，避免每次数据更新都重写全部设置。
- 当前 `useSettings.update` 是浅合并；新增嵌套组件设置时提供按组件更新的入口，避免覆盖其他组件配置。
- 小组件挂载在应用布局层，不进入图谱节点、边或物理模拟；即使书签为空，小组件也可使用。
- 使用共享的浮层协调和输入焦点规则，覆盖搜索、设置、图谱菜单、ActivityDock 与新组件。
- 跨标签页读写使用存储变化订阅；天气并发请求采用同源锁加持久缓存的方式评估实现，测试锁持有页关闭后的恢复。
- 同时保留 Chrome API 和开发模式存储适配，自动化测试中的 mock 不调用真实天气服务。开发预览在主动启用、选择城市后可以连接真实服务。
